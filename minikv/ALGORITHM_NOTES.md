# 数据结构、算法与复杂度材料

本文件为报告 Part 1、Part 2 和复杂度分析提供素材，不是可直接提交的报告正文。

## 一、数据结构组织

系统结构图：`results/figs/structure.png`；可编辑源文件：`results/structure.dot`。

- **物理内存数组**：每个 `Block` 保存所属请求 ID 和已使用 token 数。
- **哈希桶数组**：共有 4093 个桶，通过 `Request::hashNext` 形成冲突链。
- **请求逻辑块链表**：每个 Request 保存 `head` 和 `tail`；每个 BlockNode 保存物理块编号和下一节点指针。
- **逻辑与物理位置分离**：例如 A 的逻辑顺序可以是 0→1→4，节点中的 index 用于访问物理数组，并不要求物理相邻。

哈希使用无符号 32 位滚动计算 `h=h*131+字符值`，最后对 4093 取模。无符号溢出按模 2³² 回绕。查找必须比较完整 ID，而不只是哈希值。

## 二、连续分配 allocate

```text
若 count≤0 或 ID 已存在：失败
need ← (count−1)/S + 1
若 need>N：失败
按物理编号递增扫描，累计当前连续空闲段长度
首次找到长度为 need 的空闲段后停止
若未找到：失败
创建 Request，依次填入该区间并建立 BlockNode 链表
将 Request 插入对应哈希桶
成功
```

首次满足要求的区间同时具有最小可行起点。所有容量检查先于状态修改，因此普通参数／容量失败不改变状态；不在此宣称对 `new` 抛异常提供强异常安全保证。

## 三、分页分配 allocate

```text
检查 count 和重复 ID
need ← ceil(count/S)
遍历全部物理块，统计空闲块数
若空闲块不足 need：失败
创建 Request
按物理编号递增选择前 need 个空闲块
填入 token，建立请求的逻辑链表
将 Request 插入对应哈希桶
成功
```

## 四、追加 append

```text
查找 Request；若不存在或 count≤0：失败
room ← S − 尾块已使用数量
extra ← max(0, count−room)
need ← ceil(extra/S)

连续策略：检查尾块右侧紧邻的 need 个块全部存在且空闲
分页策略：遍历全部物理块，确认空闲总数不少于 need
若检查失败：保持原状态并返回失败

先填充原尾块，再分配新块并追加 BlockNode
增加 Request 的 token 总数
成功
```

**源码特有行为**：当前分页实现即使 need=0，也会遍历整个物理数组统计空闲块。因此不能直接套用“尾块有容量时 append 为 O(1)”的通用结论。

## 五、释放 free

```text
计算哈希桶，使用指向链指针的指针定位匹配 ID
若不存在：失败
从桶链中摘除 Request
遍历请求的 BlockNode 链：清空物理块 owner/used 并删除节点
删除 Request
成功
```

该删除方法统一处理桶首、中间和尾部节点。析构还需遍历所有桶，释放剩余 Request、BlockNode、桶数组和物理数组。

## 六、复杂度

设 N 为物理块数，R 为活跃请求数，L 为 ID 长度，α=R/4093，k 为新增块数，b 为请求已有块数。记 H 为实际哈希查找代价：均匀散列假设下期望 O(L(1+α))，最坏 O(LR)。题目限定 L≤32 时，可把 ID 长度视为常数。

| 操作 | 策略 | 最好情况 | 最坏情况 | 平均／期望情况 |
|---|---|---|---|---|
| lookup | 两种相同 | O(L)，桶首命中或空桶 | O(LR)，全部冲突 | O(L(1+α))，依赖散列假设 |
| allocate，合法且 need≤N | 连续 | O(H+k)，开头即满足 | O(H+N+k) | O(H+期望扫描块数+k)，依空闲段分布 |
| allocate，合法且 need≤N | 分页 | Θ(N+k)+H | O(H+N+k) | Θ(N+k)+H，必做全数组计数 |
| append，合法请求和数量 | 连续 | O(H)，不需新块 | O(H+k) | O(H+E[k])，可能提前检查失败 |
| append，合法请求和数量 | 分页 | Θ(N)+H | O(H+N+k) | Θ(N+k)+H |
| free，ID存在 | 两种相同 | O(H+b) | O(LR+b) | O(L(1+α)+b) |

非法参数和明显超大申请可能提前返回，不能把这种快速拒绝与成功操作的最好情况混为一谈。append 的总 token 数遵循题目有效输入不超过整数范围的约定。

## 七、独立计时方法与解释

`harness/bench.cpp` 使用优化编译、预热和五次重复，汇总取中位数；计时区间不做显示解析和输出，状态重置在计时之外。

- lookup：R=10、100、1000、10000，每次重复 10⁶ 次查询，一半命中、一半未命中。
- allocate：N=500、1000、2000、4000、8000，比较空内存和高编号端空闲。
- append：分别测试尾块有余量，以及尾块已满需要新块（`append_new`）。

高端空闲布局中的 `append_new`：连续策略右侧被占而快速失败，分页策略扫描后成功；两者不是相同成功路径，需结合操作结果解释。

原始五次结果见 `results/raw/benchmark.csv`；中位数见 `results/tables/benchmark_median.csv`；理论对照见 `table2_theory_vs_measurement`。

曾测得尾块有余量时，连续追加约25～30 ns，而分页从 N=500 时约131 ns 增至 N=8000 时约2058 ns，与源码的全数组扫描一致。绝对数值以当前 CSV 为准，会随系统调度和频率变化。对短操作，计时器开销不可忽略，有限规模实验不能证明渐进复杂度。
